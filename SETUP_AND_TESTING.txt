 STEP 1-A  Start the PostgreSQL Database Container
────────────────────────────────────────────────────────────────────────────────

  docker run -d ^
    --name honeynet-database ^
    -e POSTGRES_USER=honeynet ^

 SECTION 7 — TROUBLESHOOTING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PROBLEM: "Port already in use" / EADDRINUSE / [Errno 10048]
  FIX    : Find and stop what is using the port:
             netstat -ano | findstr :3000
             taskkill /PID <PID> /F
           Or simply kill all Node.js processes:
             taskkill /IM node.exe /F

  PROBLEM: "Cannot connect to PostgreSQL" / EACCES / password auth failed
  FIX    : Check Docker is running and container is up:
             docker start honeynet-database
             docker ps
           Verify .env has DB_PORT=5434 (not 5432).

  PROBLEM: Python virtual environment not found / ModuleNotFoundError
  FIX    : Recreate the venv (from ml-service folder):
             python -m venv venv
             .\venv\Scripts\Activate.ps1
             pip install -r requirements.txt
             pip install flask pyftpdlib

  PROBLEM: Phone/second laptop cannot open the dashboard
  FIX    : 1. Confirm devices are on the same Wi-Fi network.
           2. Run the firewall rule from Section 4 (as Administrator).
           3. Confirm your Wi-Fi IP is still 192.168.1.40:
                ipconfig
              Look for "Wireless LAN Wi-Fi" → IPv4 Address.
           4. If the IP changed, update the Vite proxy or use the new IP.

  PROBLEM: "FTP: Connection refused" on port 2121
  FIX    : Start the FTP honeypot in a new terminal (Section 2, Terminal 4).

  PROBLEM: Dashboard shows 0 HTTP/FTP/Telnet/MySQL events
  FIX    : The backend auto-ingests existing log entries on first startup.
           Trigger new events by visiting http://192.168.1.40:8080 or running
           the FTP/Telnet/MySQL tests in Section 5.

  PROBLEM: ML service returns 503 / connection refused
  FIX    : Restart Terminal 1 (the uvicorn ML service).
           Events are still stored in the database; ML runs when it reconnects.

  PROBLEM: "SCRAM authentication error" in Node.js
  FIX    : Password mismatch in .env vs database.
           Reset inside Docker:
             docker exec -i honeynet-database psql -U postgres -c ^
               "ALTER USER honeynet WITH PASSWORD 'honeynet123';"
           Confirm .env has: DB_PASSWORD=honeynet123

 SECTION 8 — WHAT THE AI DOES (Architecture Summary)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Every incoming honeypot event follows this pipeline:

  [Attacker Device]
       │
       ▼
  [Honeypot] (SSH / HTTP / FTP / Telnet / MySQL)
       │  writes JSON log
       ▼
  [Log Watcher] (Node.js — src/services/logWatcher.js, dionaeaWatcher.js)
       │  detects new line, normalises event fields
       ▼
  [Event Processor] (src/services/eventProcessor.js)
       │  stores raw event in PostgreSQL
       │
       ├──► [GeoIP] ip-api.com (free, cached) → country, city, org
       │
       ├──► [ML Client] POST http://localhost:8001/classify
       │         Isolation Forest anomaly detection
       │         Autoencoder reconstruction error
       │         → Returns: severity (LOW/MEDIUM/HIGH/CRITICAL), score
       │
       ├──► [Adaptation Service] (if severity = HIGH)
       │         Dynamically changes SSH banner
       │         Modifies honeyfiles (fake .env, SSH keys, AWS creds)
       │         Triggers Cowrie restart
       │
       └──► [Alert Service] (if ENABLE_ALERTS=true)
                Sends Slack / Discord / webhook notification

  [PostgreSQL Database]
       │  stores events, attackers, sessions, adaptations
